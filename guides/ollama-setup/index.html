Guides

Set up Ollama on your Mac

Ollama is an app that runs a language model on your Mac. SpeakWith can ask it for a session title and a polish, and, on the direct download, for the short summary above Related. There is no API key, and the transcript stays on the machine. You give up the hosted model's punctuation and the way it phrases a title. The names in the drawings are examples.

Why a local model

A monthly membership's allowance is not spent, and the session text is not sent to a service. That is the reason to flip the switch. A local model is not a discount copy of the hosted one.

Open Settings, Session AI, and set Provider to Ollama. Titles and polish follow that one choice together. Feedback has no model row of its own. It uses the Title model tag.

The rest of this page is the Mac. iPhone and iPad have no Ollama provider, and they cannot reach a model running on your computer.

Install it, and leave it running

Confirm the app from the menu bar and from Terminal before you pull a model.

  1. Install Ollama. Use the installer from Ollama. A menu-bar item appears, and the app is set to open at login. That item is the daemon SpeakWith talks to.

    For example

    After a restart the item should already be up, without you opening Ollama by hand.

  2. Ask for the version. In Terminal, run ollama --version. A version line means the command is on your path. The number in the drawing is an example. Any current release is enough.

    For example

    command not found means the install did not land on your path, or this Terminal was opened before the install finished. Open a new window and try again.

  3. Do not quit that menu-bar item. SpeakWith will not launch Ollama for you. Quitting the item is what later shows up as a connection failure, with no title written.

Pull a tag, then read the list

The NAME column of ollama list is the only menu there is. SpeakWith never asks the daemon which tags are installed, so the field in Settings is plain text.

  1. Pull a model that can chat. llama3.1:8b and qwen3:8b are the tags that suit a title. The first pull downloads the weights, several gigabytes. An embedding model such as nomic-embed-text can appear in the list and still cannot write a title.

    For example

    ollama pull llama3.1:8b

    ollama pull qwen3:8b

  2. Read ollama list. Copy from the NAME column. Size is only there so you can see what the download cost in disk. SpeakWith does not show this table.
  3. Keep the colon. llama3.1:8b and llama3.1:latest are different tags. The Title model field ships as llama3.1, and a name with no colon is treated as that name plus :latest. A Mac that pulled only llama3.1:8b will refuse llama3.1.

    For example

    The refusal names the tag you asked for: model 'llama3.1' not found.

    Pasting llama3.1:8b, colon and all, is the fix.

Type that tag into SpeakWith

The Ollama section is in Settings, Session AI, and only after Provider is set to Ollama. Its first sentence says the daemon must be running, and it prints the address on this Mac. There is no field for that address, and nothing in Settings changes it.

  1. Title model. Replace the placeholder with a NAME from ollama list, colon included. llama3.1:8b is the usual replacement for the shipped llama3.1.

    For example

    Leave the field as llama3.1 only when ollama list actually has llama3.1:latest.

  2. Polish model. Empty means polish reuses the Title model tag. Type a second tag only when polish should run on a different model. The first polish on that other tag waits for a cold load. Keep warm, the last row, holds that same tag only. Warming both would have the daemon drop one to keep the other.
  3. One provider for both jobs. Polish cannot stay on OpenAI once titles are local. The Provider row is the only switch, and it covers both.

Context, and how long it stays loaded

Context offers 4k, 8k, 16k, and 32k. A fresh install starts at 16k, which is what the drawing shows. Each title asks for a window big enough for that session, and never bigger than the step you picked. A larger step reserves more memory. A short session does not fill the step. When the text does not fit, the AI sidebar says so before you generate, and the heading is taken from the start of the session.

Keep warm is how long the title model stays in memory after a title: Ollama default, 15 minutes, 1 hour, 4 hours, or Until quit. A fresh install uses Ollama default, leaving the timing to Ollama. The drawing picks 15 minutes only so the row shows a duration. Until quit holds the model until you quit SpeakWith, and SpeakWith releases it on the way out.

Changing Context reloads the model even when the tag is the same. Count on the same wait as a first load.

Warm it before the first title

Warm now sits in the AI sidebar, next to the session title. It loads the title model at the context the following title will request, so Generate finds the model already resident. An 8B model can take about a minute the first time. Spend that wait on Warm now.

Unload frees the memory. If nothing was loaded, the press is harmless.

The line under the model name is the fit report for the session you have selected. Orange means the cap will trim it.

The summary above Related

Finding earlier sessions always runs on the Mac, with a model that lives inside SpeakWith. The paragraph above that list is a separate request. The direct download can hand it to Ollama. The Mac App Store build has no such control, which is why the drawing carries a banner.

In Settings, Related, under Summary model, choose On this Mac. Local summary model is another free-text tag. Leave it blank and the summary follows Title model. A different tag starts cold, and a different context size reloads the model even when the name matches.

With On this Mac selected, that paragraph is written locally and the allowance is untouched. OpenAI, the other item in the menu, sends titles and short excerpts off the machine and meters the call.

Two lines you may see in red

A missing tag. The sidebar shows Ollama HTTP 404, then the daemon's note that the model was not found, in the shape model 'llama3.1' not found. The usual cause is the shipped default: the field still says llama3.1, you pulled llama3.1:8b, and the daemon looks for llama3.1:latest. Paste the NAME column in full.

The daemon is stopped. The line reads cannot connect to 127.0.0.1. No heading is written. Open the menu-bar item again. There is no Settings row that starts Ollama.

A name that cannot chat fails too. If Title model is the embedding tag from the pull section, switch it to a chat model.

What never calls Ollama

Transcription. The recording and the transcript are produced on the device. The daemon is not in that path.

Matching earlier sessions. That search never consults Ollama, including when an embedding tag is what you pulled.

iPhone and iPad. Those apps cannot reach Ollama at all.
